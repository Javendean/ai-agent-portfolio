The pattern I keep applying

Unstructured input→ LLM extraction→ Typed validation→ ✓ System of record
↳ on failure → Targeted correction prompt → retry (bounded)
↳ on low confidence → Flag for human + written reason

Every attempt, error and applied correction is written to an audit trail. Exhausting retries returns the best available result with explicit error flags — never a silent failure.

Two delivered systems

Verity

Python 3.12 · FastAPI · Pydantic 2 · Docker · Kubernetes · HubSpot v3

Turns unstructured sales notes into validated CRM records. A single LLM call gets this approximately right and fails silently; this service fails loudly and repairs itself.

  • Instructional error repair. Not “invalid date” but “end of Q2 must be YYYY-MM-DD; Q2 ends June 30.”
  • Calibrated uncertainty. Confidence scores, requires_human_review, written review reasons, ambiguity notes, estimate flags.
  • Provider failover. Abstract base class, registry, and an orchestrator that fails over on rate limits, with per-token cost tracking.
  • 82 tests, whole suite under half a second.

LCC Management System

SvelteKit · Supabase/Postgres · Vercel · Twilio · live in production

Contact management, segmentation and bilingual SMS campaigns for a non-profit. ~10 admin users, ~350 contacts. Real users, real regulatory exposure.

  • Compliance as architecture. TCPA opt-outs are never deleted — re-subscribing sets a timestamp so the original opt-out time survives, which is the value regulators ask for. Every send path filters on active opt-outs.
  • A cost bug caught by a test. Spanish templates force UCS-2 encoding (67 chars per segment against GSM-7's 153). One template was 3 segments in Spanish and 1 in English — roughly double the cost per campaign. Fixed, then locked behind an automated segment-budget test so it cannot regress.
  • Governed access. New accounts require explicit admin approval; no self-serve signup.
