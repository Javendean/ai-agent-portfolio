What I do

A check that cannot be shown to fire is not evidence.

So I write the check first, then I plant the error it is supposed to catch and make it prove it caught it. Three habits do most of the work.

Independent oracles

A check is worth something only when its input cannot be influenced by the thing it checks. If the checker and the checked read the same source, their agreeing tells you nothing you did not already assume.

Typed contracts, bounded repair

A validation failure is more useful as an instruction than as an exception. Turn each one into the specific repair it asks for, bound the retries, and let whatever comes out carry its own error flags.

Authorisation in the database

Rules that live in route guards get a second copy the moment a second entry point appears. Public intake forms should write to the same tables the admin app reads, under the same policies, or the two will drift.

Mapping, extraction and authorisation all reduce to one question: whether an output can be trusted in a system of record.

A mapping can reconcile to the cent and still be wrong by $309,245.88.

So I do not let a system grade its own output.

01

TIE-OUT

Chart of accounts mapping for roll ups

It caught a mapping error that left the entity tying to the cent and gross profit off by $309,245.88.

About 3,200 lines of Python over DuckDB and dbt. It maps an acquired company's chart of accounts onto the group chart and refuses to publish a close pack it cannot stand behind. 124 tests passing in 47.95s, run 2026-09-09.

The hard part is that the dangerous error is arithmetically perfect. The disproof script plants COGS - Materials into Rent and Occupancy. Both accounts are debit normal and the row is assigned exactly once, so conservation and sign preservation pass, correctly. Only the subtotal oracle fails, because it reads something the mapper never sees. That is an independent oracle, not a tighter tolerance.

The harness argues against its own numbers. Name similarity ranks at 0.727 AUC but scores 30/51 = 58.8% top 1, and 8 of the 21 errors cross the balance sheet and P&L line, so the feature is barred from proposing a destination.

02

Verity

CRM intake that will not fail silently

On messy input every working model scored 0% first attempt and 100% final. Six models, nine trials each.

It turns unstructured sales notes into schema validated CRM records. FastAPI, Pydantic 2, 82 tests passing in 0.54s, run 2026-09-09. The provider layer registers models behind one interface and fails over automatically on rate limit errors, tracking cost per token. The repo is emet-crm-pipeline-demo, so the full capture on the case study is headed Emet CRM Pipeline rather than Verity.

The hard part is what happens on exhaustion. The captured run took 2 attempts and 8,450 ms and returned partial_success. Attempt 1 rejected 'jenny at meridian something dot com', an amount that was not a number, the stage 'early discussions' and the date 'end of Q2'. Attempt 2 set the email to null, resolved the date to 2026-06-30, and converted 'forty, forty-five K' to a midpoint of 42500.0 marked as an estimate. Four fields were flagged for human review.

The gap between 0% and 100% is exactly what the correction loop buys. The cheapest working model matched one costing about 5.9 times as much.

03

LCC Management System

Bilingual member messaging, in production

18 row level security policies. Authorisation lives in the database, not in route guards.

A SvelteKit and Supabase app that about 10 administrators use to reach 450 contacts, 0 of whom have opted out. 587 lines of SQL across 9 migrations: 18 policies, 7 tables, 11 indexes, RLS enabled on 7 tables.

The hard part is consent that survives. Opt out rows are never deleted. Re-subscribing sets resubscribed_at, so the original opt out timestamp survives, which is the value a regulator asks for, and the TCPA statute of limitations is 4 years. Every send path filters on resubscribed_at IS NULL.

Then a cost finding, measured live on 2026-09-09. The same message is 1 segment and 116 characters in English and 3 segments and 169 characters in Spanish, because accents and ¿ force UTF16 and cut the segment budget from 153 characters to 67. One live template was doing it. I fixed it and locked it behind a test that asserts a segment budget per template.

The $7.66 below is the cost that gets avoided, not a bill I paid. A separate path mints a single-use, time limited batch URL of 32 bytes from crypto.getRandomValues, marks the row used_at on first fetch so it cannot be replayed, and hands over a QR code. An iPhone Shortcut fetches the precomputed send list and dispatches from my own phone for $0, through the same recipient resolution and consent gates as the server send path. Compliance is not what gets skipped to save the money.
